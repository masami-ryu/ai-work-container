# tmux Codexサイドバー

同じtmux sessionのwindow名とCodexの状態を、左側のpaneに表示します。右クリックで改名、ドラッグで並べ替え、pane境界のドラッグで幅を変更できます。

依存はtmux、Python 3.11以降（標準の`curses`を含む）、Codex CLIです。tmux 3.4 / Codex CLI 0.166.0で確認しています。

## 導入

```bash
python3 /workspaces/ai-work-container/tools/tmux-codex-sidebar/setup.py
```

- `~/.tmux.conf`にサイドバーの読み込みを追加し、起動中のtmuxに反映します。
- Codexの`config.toml`で、端末タイトルにthread IDを含めます。`CODEX_HOME`を設定している場合はその保存先を使います。
- 既存の設定は保持します。変更前のファイルは同じディレクトリに日時付きでバックアップします。
- Codexの`tui`設定は、`[tui]`・`tui = { ... }`・`tui.notifications = false`などの記述形式に対応します。
- 設定ファイルのsymlinkを維持するため、このコンテナの永続化設定でも使用できます。
- 再実行しても読み込み設定やpaneは重複しません。

設定保存だけを行う場合は`--no-load`を付けます。tmux設定の保存先が標準と異なる場合は`--tmux-config PATH`を指定します。

導入後は、普段どおり`codex`を起動します。すでに起動しているCodexで「設定待ち」と表示される場合は、Codex内で次を実行します。

```text
/title app-name thread-id status
```

このコマンドに未対応のバージョンでは、作業終了後にCodexを再起動します。実行中の作業をサイドバーが再起動することはありません。

## 操作

| 操作 | 動作 |
| --- | --- |
| window名を左クリック | 対象windowへ移動し、直前に使っていた作業paneへフォーカス |
| 右クリック / `r` | window名を編集 |
| 改名中の`Ctrl+u` / Backspace | 名前全体を消去 / 末尾の1文字を削除 |
| 改名中のEnter / Esc | 保存 / キャンセル |
| 改名中に一覧を左クリック | 編集を取り消して、クリックしたwindowへ移動 |
| 左ボタンで名前をドラッグ | 下方向ならドロップ行の後ろ、上方向なら前に挿入 |
| ドラッグ中のEsc / 一覧外で解放 | キャンセル |
| 右側のpane境界をドラッグ | 幅を変更。別windowにも表示時に反映 |
| ホイール / `j`・`k` / 矢印キー | 一覧のスクロール / 選択位置の移動 |
| Enter | 選択windowへ移動 |
| `prefix + e` / `q` | 現在のsessionのサイドバー表示を切り替え / 非表示 |

標準のprefixは`Ctrl+b`です。反転表示は現在のwindow、下線はキー操作や編集の対象を示します。サイドバーの表示を切り替えても、作業用paneやCodexは終了しません。

最後の作業paneを`exit`などで閉じると、サイドバーも閉じてwindowが一覧から消えます。他の作業paneがある場合や、`remain-on-exit`で終了画面を保持している場合はwindowを残します。

名前の変更中は、対象行と下部の入力欄・操作案内を黄色の背景と黒い文字で強調し、入力カーソルを表示します。`Ctrl+u`で現在の名前を消して入力し、Enterで保存します。色に対応しない端末では反転と太字で強調します。

編集中もCodexの状態表示は更新します。入力中の名前と一覧の並び順は、編集を終えるまで保持します。

幅は手動の境界操作で保存します。端末全体のリサイズで一時的に幅が狭くなっても、保存した幅は保持します。背景での幅調整中に境界を動かした場合は、手動変更を優先します。

作業paneの追加・削除・入れ替えでレイアウトが変わった場合は、サイドバーを保存済みの幅へ戻します。複数ある作業paneの1つを終了しても、広がった幅が他のwindowへ伝わることはありません。

最後の作業paneの終了後、サイドバーが閉じるまで一時的に画面全幅へ広がっても、その幅を保存したり別windowへ反映したりしません。

サイドバーを設置したwindowは、その時点の名前を保持します。windowやpaneを切り替えても、実行中のプロセス名（`codex`や`python3`など）で自動的に上書きしません。名前の変更には右クリックを使います。

## 状態の意味

状態名の右に丸いランプ（`●`）を表示します。**作業中は緑、回答待ちは赤、その他は白**です。選択中・改名中もランプの色は変わりません。色に対応しない端末では状態名で識別できます。

| 表示 | 意味 |
| --- | --- |
| 作業中 | Codexのturnが実行中 |
| 回答待ち | 明示的な質問または承認への入力待ち。選択行の下部に種類を表示 |
| 完了 | 直近のturnが正常終了 |
| 未開始 | Codexが起動済みで、まだturnがない |
| 中断 / 異常 | 直近のturnが中断 / 失敗、または実行時エラー |
| 未起動 | 対象windowに実行中のCodexがない |
| 設定待ち | Codexの端末タイトルにthread IDが含まれていない |
| 不明 | 接続失敗、threadの未読込、IDを一意に特定できない場合など |
| 複数 | 1つのwindowで複数のCodexを実行中 |

「完了」は依頼全体の達成やレビュー合格を意味しません。通常の返答文に書かれた質問は、明示的な質問UIと区別して扱います。

## 仕組みと対象範囲

- 各windowに通常のpaneを1つ作り、PythonのTUIを表示します。tmux本体の改造や入れ子のtmuxは不要です。
- 導入・表示再開時に全windowのサイドバーを用意し、新しいwindowにも自動で追加します。切替時にpaneを作るレイアウト変更を避けます。
- 非表示のwindowも共通の状態取得結果で描画し、内容が変わったときだけ再描画します。切替先に前回表示時の状態を残しません。
- 状態は既存のCodex daemonのUnix socketから取得します。TCPポートや追加の監視daemonは作りません。
- 端末タイトルのthread IDを、daemonが保持するIDと一意に照合します。省略されたIDが複数候補に一致する場合は「不明」にします。
- session内の1つのサイドバーが約1秒間隔で状態を取得します。取得担当はwindow切替や並べ替えでは変わらず、そのpaneを閉じた場合に引き継ぎます。idle中は最新turnの情報を約2秒間キャッシュします。
- thread IDの照合用prefix・状態ラベル・補足だけを、ユーザー専用の一時ディレクトリで共有します。取得中は直前の結果を表示し、遅れて届いた古い結果では上書きしません。実際の取得失敗や10秒以上の更新停止は「不明」として扱います。
- `thread/read`は履歴を含めず、`thread/turns/list`も`itemsView: notLoaded`で読みます。返されたメタデータは状態判定にだけ使い、プレビューなどを表示・保存しません。
- Codexの承認への回答、プロンプト送信、threadの開始・停止・再開は行いません。
- 設定の追加先は`~/.tmux.conf`とCodexの`[tui].terminal_title`です。tmuxでは専用番号のhooks、`prefix + e`、`mouse on`を使用します。

1windowにつきCodexは1つを対象とします。補助のshell paneは併用できます。`--no-daemon`や別サーバーに接続したCodexの状態は標準daemonでは取得できません。必要な場合は`codex --remote unix://`で標準daemonを明示します。

作業paneをzoomすると、標準paneであるサイドバーも隠れます。端末幅が50桁未満の場合は新しいサイドバーを作りません。任意のレイアウト再配置で左位置を保つ処理、複数clientごとの幅、複数sessionへリンクされたwindowは対象外です。

tmux 3.4には、右クリックから左クリックなど、異なるボタンへ約300ms以内に切り替えると押下を破棄する挙動があります。右クリック直後のドラッグが反応しない場合は、少し間を置いて操作します。[tmux本体の処理](https://github.com/tmux/tmux/blob/3.4/server-client.c)に由来する制約です。

## 開発・検証

```bash
python3 -m unittest discover -s tools/tmux-codex-sidebar -v
```

テストは専用socketの一時tmux serverを使います。疑似端末からのマウス入力で、改名・並べ替え・幅変更・連続切り替え・ハイライト・改名中からの切り替えを確認します。設定パスの展開、生成・非表示・幅変更の競合、作業paneの復元、改名中の状態更新も検証します。Codexへのモデルリクエストは発生しません。

最後の作業paneの終了、`remain-on-exit`の保持、空のwindowの整理とpane追加が競合する場合も検証します。複数作業paneの終了・入れ替え時の幅保持と、上下分割後の手動リサイズも検証します。

主なファイルは、TUIとtmux操作の`sidebar.py`、状態取得の`codex_state.py`、設定導入の`setup.py`です。

仕様の参照先: [tmux公式マニュアル](https://github.com/tmux/tmux/blob/3.4/tmux.1)、[Codex公式App Server API](https://learn.chatgpt.com/docs/app-server)、[Codex公式タイトル設定](https://learn.chatgpt.com/docs/config-file/config-sample)。
