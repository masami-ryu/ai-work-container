## プランレビュー/修正

### レビュー

`/code-reviewing` スキルに委譲。`/code-reviewing ai/plans/[対象プラン]/plan.md`（または `ai/plans/[対象プラン].md`）で実行。

Standard/Comprehensiveワークフローではプラン作成後にレビュー実行を推奨。

### レビュー結果に基づく修正

1. **レビューファイル読み込み**: `ai/reviews/` から対応するレビューファイルを `Read` で取得
2. **重要度別対応**:
   - 🔴 高: 必須修正（前提の誤り、タスク設計の重大不備等）
   - 🟡 中: 推奨修正（曖昧な完了条件、不足している分析等）
   - 🟢 低: 判断に委ねる（表現改善、補足情報等）
3. **修正箇所の特定**: レビュー指摘のID・セクション番号と下記対応表から修正対象セクションを特定し、必要に応じて `Grep`/`Glob` で再調査
4. **修正実施**: プランを編集
5. **変更履歴記録**: プランの「変更履歴」セクションに対応内容を記録
6. **品質検証**: 品質チェックリストを再実行
7. **ステータス更新**: 下記ルールに従いステータスを更新

### レビュー評価観点とプランセクションの対応

| レビュー評価観点 | 主な修正対象セクション |
|---|---|
| 完全性 | 1.概要（スコープ）、2.要件と制約 |
| 実現可能性 | 3.実装ステップ（対象ファイル）、7.依存関係 |
| タスク設計 | 3.実装ステップ（Phase分割・タスク内容） |
| 測定可能性 | 3.実装ステップ（完了条件）、4.テスト計画、5.成功基準 |
| リスク対応 | 6.リスクと対策 |

### ステータス遷移ルール

<!-- 依存: .claude/skills/code-reviewing/references/plan-review-guidelines.md の移動/改名時は本リンクも更新 -->
評価スコア基準は [plan-review-guidelines.md](../../code-reviewing/references/plan-review-guidelines.md) を参照。

| 遷移 | 条件 |
|------|------|
| Draft → Review | レビュー依頼時 |
| Review → Approved | 全観点スコア4以上かつ🔴高の指摘なし |
| Review → Draft | 🔴高の指摘あり → 修正後に再レビュー |
| Approved → In Progress | 実装開始時 |
| In Progress → Completed | 成功基準を満たした時 |
