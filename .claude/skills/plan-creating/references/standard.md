## 適用条件

- 中程度の複雑さ
- 3-10ファイルに影響
- 既存パターンの活用が可能

## 適用例

- 新機能追加
- 複数ファイルのリファクタリング
- API エンドポイントの追加
- データベーススキーマの変更

## プロセス

### 1. 目的理解

- ユーザーの要求を正確に理解
- スコープと期待される成果を定義
- 前提条件を確認

スコープや優先度が曖昧な場合は`AskUserQuestion`で確認（SKILL.md参照）。

### 2. 情報収集

- 情報収集の一般手順は SKILL.md の「共通プロセス」を参照（Standardでは依存関係/技術的制約まで含めて確認）

**完了条件**:
- [ ] 対象ファイルの特定完了
- [ ] 既存パターンの把握完了
- [ ] 依存関係の理解完了
- [ ] 技術的制約の把握完了

### 3. 設計検討

- コードベース内の既存パターン・規約を優先的に参照
- 補助的に`WebFetch`で最新情報を取得
- 業界標準の設計パターンとベストプラクティスを確認
- 複数の実装案を比較

複数の妥当なアプローチが存在する場合は`AskUserQuestion`で選択を促す（SKILL.md参照）。

### 4. プラン作成

- 実行可能なアクションアイテムに変換
- Phase/タスク単位で整理
- 完了条件を明記
- リスクと対策を含める

### 5. 検証

設計検討後とプラン作成後の2回検証:

#### 設計検討後
- [ ] 設計案が要件を満たしているか
- [ ] ベストプラクティスに準拠しているか
- [ ] リスクが特定されているか

#### プラン作成後
SKILL.mdの「品質チェックリスト」を実行。重大リスク検出時は`AskUserQuestion`で許容度を確認。

### 6. 出力

- テンプレート [assets/plan-template.md](../assets/plan-template.md) を使用
- `ai/plans/YYMMDD_HHmm_[概要].md`に保存（`HHmm` はJST/UTC+9）
- ステータス: Draft
- 各タスクの実装指示が必要な場合、[assets/task-template.md](../assets/task-template.md) で個別指示書を作成
- プラン保存後、`/code-reviewing ai/plans/[作成したプラン].md` でレビュー実行を推奨
