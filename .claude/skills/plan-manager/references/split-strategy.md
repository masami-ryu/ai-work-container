# プラン分割戦略ガイド

> このガイドは **セッション分割** の判定基準を定義する。プランの **種別（Express / Standard / Comprehensive）** の判定は plan-creating の管轄であり、本ガイドの対象外。plan-manager はプランのタスク数に基づいてセッション分割を行う。

## 1. 分割判定基準

| タスク数 | 判定 | 管理レベル | 説明 |
|---------|------|----------|------|
| 2以下 | 対象外 | — | plan-manager の管理対象外 |
| 3-5 | 分割不要 | 小規模 | 単一セッションで実行。振り返りのみ（plan.md 末尾に追記） |
| 6-9 | 分割推奨 | 中規模 | 2-3セッションに分割。progress/ にセッション記録を保存 |
| 10+ | 分割必須 | 大規模 | 3セッション以上。全機能適用（分割 + 振り返り + ゲート判定 + 引き継ぎ） |

タスク数以外の分割トリガー:

- **コンテキスト量**: 1セッションで扱うファイルが10ファイルを超える場合
- **依存関係の深さ**: 直列依存が5つ以上連なる場合（途中で区切る）
- **リスクの集中**: 不確実性の高いタスクが連続する場合

## 2. 分割パターン

### パターン A: フェーズ単位分割

**適用場面**: プランのフェーズが明確に独立している場合

- プランの Phase をそのままセッション境界にする
- 最もシンプルで推奨されるパターン
- フェーズ間の依存が小さいほど有効

### パターン B: 依存チェーン分割

**適用場面**: タスク間の依存が線形で、フェーズ境界と一致しない場合

- 依存チェーンの切れ目（出力が後続タスクの入力にならない箇所）でセッションを分ける
- セッション境界をまたぐ依存がある場合、引き継ぎ情報に依存の詳細を明記

### パターン C: サイズ均等分割

**適用場面**: 単一フェーズのタスク数が多すぎる場合

- 1セッション 2-3タスク（最大4）を目安に均等分割
- 依存関係のあるタスクは同一セッションに含める

### パターン D: リスクベース分割

**適用場面**: 不確実性が高いタスクがある場合

- 高リスクタスクを独立セッションにして早期検証
- 検証結果に応じて後続セッションのタスクを調整できる

## 3. セッションサイズの目安

| 項目 | 目安 |
|------|------|
| タスク数 | 2-3（最大4） |
| 変更ファイル数 | 10以下 |
| 初回セッション | 少なめ（1-2タスク）にして分割の妥当性を検証 |

## 4. 分割手順

1. plan.md のフェーズ構成を確認
2. タスク間の依存関係をマッピング
3. 上記パターン A-D から最適なパターンを選択（迷ったらパターン A）
4. セッション境界を決定し、各セッションの対象タスクを一覧化
5. セッション間の依存（引き継ぎが必要な情報）を明記

## 5. 分割時の注意事項

- フェーズ境界とセッション境界を合わせるのが理想
- 依存関係のあるタスクは同一セッションに含める
- 分割後のセッション数が予想より増えた場合、プラン自体の見直しを検討
- 初回セッションは少なめにして、分割の妥当性を検証する

## 6. 実績例

**コンテキスト管理実装プラン**（10タスク・6フェーズ）:

| セッション | フェーズ | タスク数 | 内容 |
|-----------|---------|---------|------|
| セッション 1 | Phase 1 | 2 | コア実装（DB + CLI） |
| セッション 2 | Phase 2 | 3 | CRUD操作 |
| セッション 3 | Phase 3-4 | 2 | 検索 + スコープ管理 |
| セッション 4 | Phase 5-6 | 3 | 鮮度管理 + 統合テスト |

→ 4セッション、各2-3タスク。フェーズ境界に概ね一致（パターン A + C の組み合わせ）。
