# 要件定義レビュー チェックリスト

以下の各項目を要件定義書に照合し、未充足の項目を指摘として報告する。

## 1. 要件整合性

- [ ] 同じ対象（ロール、データ、機能）が章ごとに矛盾なく定義されている
- [ ] 原則ルール（「不可」「禁止」等）に例外がある場合、原則側から例外への相互参照がある
- [ ] 「未決事項」と「解決済み項目」の間に重複・逆転がない
- [ ] 例外条件（境界値、失敗時、手動対応時）が定義されている
- [ ] 消化順序（FIFO等）が必要な資源（ポイント、プリペイド、有給等）にルールが定義されている

## 2. 実装可能性

- [ ] 計算仕様に適用順序がある（例: 集計→比較→丸め）
- [ ] 端数処理のタイミングと適用単位（明細単位/日次/月次）が明示されている
- [ ] 必須データの取得元・更新元・正本が明示されている
- [ ] 税込/税抜の扱いが全テーブル・全計算で一貫している
- [ ] 複雑なビジネスロジックに具体的な計算例が付与されている

## 3. 認証・権限・監査

- [ ] ロール定義と機能権限が一致している
- [ ] 共有アカウント運用時の統制（承認、理由記録、操作証跡）が定義されている
- [ ] 監査ログ要件（誰が/いつ/何を）が実運用で満たせる
- [ ] 金銭データ変更の操作者特定手段が確保されている

## 4. 非機能要件

- [ ] 可用性要件に対象範囲（顧客Web/管理画面/API）と集計単位がある
- [ ] 性能要件に測定条件（対象処理、同時接続、評価指標P95等）がある
- [ ] データ保持要件に対象データ別の保持年数と削除方針がある

## 5. 法令準拠

- [ ] 労基法関連（有給付与の出勤率要件、残業計算、変形労働時間制）への適合が定義されている
- [ ] 個人情報保護法関連（暗号化at rest、利用目的の明示、削除要求対応、第三者提供）が定義されている

## 6. 外部連携

- [ ] 外部システム障害時のフォールバック（手動入力代替フロー、復旧後のマージ方針）が定義されている
- [ ] 書き込み操作の冪等性（リトライ時の重複防止）が考慮されている
- [ ] 部分成功時の補償処理（取り消し or 再送）が定義されている
- [ ] スクレイピング/API連携のUI変更・仕様変更時の検知・通知方針がある

## 7. データ境界

- [ ] マスタデータの全社横断/店舗単位の所有権が明確に定義されている
- [ ] 同一エンティティの属性が全社管理と店舗管理で矛盾していない
- [ ] 外部システムIDの保持粒度（顧客単位 vs 顧客×店舗単位）が定義されている
