# Plan Review Applier

レビュー指摘の妥当性を分析し、妥当な指摘に基づくプラン修正を `/plan-creating` に委譲する。

- **入力**: レビューファイルパス（`ai/reviews/*.md`）、プランファイルパス（`ai/plans/*.md`）の2つを引数で受け取る

## プロセス

### Step 1: 入力読み込み

1. 引数で指定されたレビューファイルとプランファイルを `Read` で読み込む
2. レビューファイルから指摘を抽出する
   - パース対象: `## 改善提案` 配下の `### 🔴 重要度: 高` / `### 🟡 重要度: 中` / `### 🟢 重要度: 低`

### Step 2: 妥当性分析

レビューの各指摘を以下の判定基準で分類する：

- **妥当** → Step 3 で修正対象
- **要確認** → `AskUserQuestion` でユーザーに判断を委ねる。回答に基づき「妥当」または「不適切」に再分類
- **不適切** → 修正対象外。サマリーで理由とともに報告

#### 検証ルール
- CLAUDE.md / works/CLAUDE.md の規約と矛盾する指摘は「不適切」
- プランテンプレートに存在しないセクションの追加提案は「要確認」
- プランの「スコープ > 対象外」に明記された範囲への指摘は「不適切」
- 優先度に関わらず、妥当な指摘は全て修正対象とする

### Step 3: プラン修正の委譲

妥当と判定した指摘の一覧を `/plan-creating` に渡し、プラン修正を委譲する。修正手順の詳細は [plan-revision.md](../plan-creating/references/plan-revision.md) に従う。

### Step 4: 結果報告

修正完了後、以下の形式でサマリーを出力する：

```
## 反映結果サマリー
- 対象プラン: `ai/plans/YYMMDD_HHmm_[概要].md`
- 参照レビュー: `ai/reviews/YYMMDD_HHmm_[概要]_レビュー.md`

### 妥当（反映済み）
- [指摘概要] → [修正内容]

### 要確認 → 反映 / 除外
- [指摘概要] → ユーザー判断: [反映 or 除外]

### 不適切（未反映）
- [指摘概要] → 理由: [未反映の理由]
```
