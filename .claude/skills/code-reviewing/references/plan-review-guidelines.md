# プランレビュー観点ガイドライン

## プランレビュー固有のプロセス

プランレビューではPhase 2-3を以下のように読み替える:

- **Phase 2（詳細分析）**: プランが参照する対象ファイルを `Read`/`Grep` で確認し、プランの前提（ファイル構造・既存実装・依存関係）が実態と一致するか検証する
- **Phase 3（ベストプラクティス参照）**: プランが採用するアーキテクチャ・ライブラリの選定妥当性を確認する必要がある場合のみ実施

## 評価観点

### 1. 完全性

- すべての要件がプランに反映されているか
- スコープ（対象/対象外）が明確か
- 前提条件が漏れなく記載されているか

### 2. 実現可能性

- 対象ファイルが実在し、プランの前提と一致するか（Phase 2で検証）
- 技術的制約との整合性（既存アーキテクチャ・依存関係）
- タスクの粒度が実装可能なサイズか

### 3. タスク設計

- 各タスクが具体的なアクション動詞で記述されているか
- タスク間の依存順序が正しいか
- Phase分割が論理的に妥当か

### 4. 測定可能性

- 完了条件が客観的に判断可能か（「〜を改善」ではなく「〜が通ること」等）
- 成功基準が具体的で検証手段があるか
- テスト計画が完了条件と対応しているか

### 5. リスク対応

- 主要リスクが識別されているか
- 各リスクに対策が記載されているか
- 破壊的変更・後方互換性への言及があるか（該当する場合）

## 評価スコア基準

| スコア | 基準 |
|--------|------|
| ⭐⭐⭐⭐⭐ (5) | 問題なし。そのまま実装着手可能 |
| ⭐⭐⭐⭐☆ (4) | 軽微な改善点あり（実装に支障なし） |
| ⭐⭐⭐☆☆ (3) | 中程度の改善が必要（一部曖昧・不足あり） |
| ⭐⭐☆☆☆ (2) | 重要な問題あり（前提誤り・タスク設計不備等） |
| ⭐☆☆☆☆ (1) | 大幅な修正が必要（実装着手不可） |
