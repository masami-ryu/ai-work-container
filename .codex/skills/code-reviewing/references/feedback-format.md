# フィードバック形式

## 基本形式

すべての指摘は以下の形式で記載する:

```markdown
**[ファイル名:行番号]** 指摘内容

**カテゴリ**: code_quality|security|performance|test|design
**重要度**: 高|中|低

**根拠**:
- [公式ドキュメントURL]
- [ベストプラクティス参照]

**影響範囲**（Grep分析結果）:
- 直接参照: X箇所
  - ファイル:行番号
  - ...

**推奨**: 改善提案

**コード例**:
\```language
// 推奨される実装
\```
```

## 種別ごとの適用ルール

| フィールド | PR / git差分 | メタレビュー | プランレビュー |
|------------|:---:|:---:|:---:|
| ファイル名:行番号 | 必須 | 元レビューの指摘箇所を引用 | ID（TASK-XXX, REQ-XXX, RISK-XXX等）またはセクション番号で箇所を特定 |
| カテゴリ | 必須 | 必須 | 必須 |
| 根拠 | 推奨 | 推奨 | 推奨 |
| 影響範囲（Grep分析） | 推奨 | 省略可 | 省略可 |
| コード例 | 推奨 | 省略可 | 省略可 |

## エビデンスの種類

1. **公式ドキュメント**: context7によるライブラリドキュメント（推奨）、WebFetchによる公式サイト、または Codex 知識に基づく参照
2. **コード例**: 推奨される実装パターン
3. **影響範囲**: Grep分析結果

## エビデンス付与率

- **目標**: 全指摘の80%以上にエビデンスを付与する
- エビデンスの種類（URL、コード例、影響範囲分析）のいずれか1つ以上を含めれば付与済みとみなす
- 重要度:高の指摘は必ずエビデンスを付与する
- 重要度:低の指摘はエビデンス省略可
