# Slack Bridge セットアップガイド

Claude Code の対話UI（権限確認・AskUserQuestion）を Slack にバイパスし、離席中でもスマホから応答できるシステム。

## 前提条件

- Claude Max プラン加入済み
- Slack ワークスペース利用可能（無料プランで可）
- Python 3.10+
- uv パッケージマネージャ

## 1. Slack App 作成

### 1.1 App 作成

1. https://api.slack.com/apps → **Create New App** → **From scratch**
2. App Name: `claude-bridge`（任意）
3. Workspace: 自分のワークスペースを選択

### 1.2 Socket Mode 有効化

1. **Settings > Socket Mode** → ON

### 1.3 App-Level Token 生成

1. **Settings > Basic Information** → **App-Level Tokens**
2. **Generate Token and Scopes**
3. Token Name: `socket-mode`
4. Scope: `connections:write`
5. **Generate** → トークン（`xapp-...`）をコピー → `SLACK_APP_TOKEN`

### 1.4 Bot Token Scopes 設定

1. **Features > OAuth & Permissions** → **Scopes**
2. Bot Token Scopes に追加:

| スコープ | 用途 | 要否 |
|---------|------|------|
| `chat:write` | メッセージ投稿・更新 | **必須** |
| `channels:read` | チャンネル情報取得 | **必須** |
| `commands` | スラッシュコマンド（`/claude`, `/claude-status`, `/claude-stop`） | **必須** |
| `channels:history` | パブリックチャンネルのメッセージ読み取り（スレッド返信による回答） | **必須** |

### 1.5 スラッシュコマンド設定

1. **Features > Slash Commands** → **Create New Command** で以下の3コマンドを追加:

| コマンド | Short Description | Usage Hint |
|---------|-------------------|------------|
| `/claude` | Start a Claude session | `[prompt]` |
| `/claude-status` | List active sessions | |
| `/claude-stop` | Stop a session | `[session_id]` |

2. 各コマンドの **Request URL** は入力不要（Socket Mode のため自動ルーティング）
3. **Save** をクリック

### 1.6 Event Subscriptions 設定

1. **Features > Event Subscriptions** → ON
2. **Subscribe to bot events** に追加:

| イベント | 用途 |
|---------|------|
| `message.channels` | パブリックチャンネルでのスレッド返信による質問回答 |

**注意**: `message.channels` はパブリックチャンネル限定です。プライベートチャンネル（`message.groups`）は追加しないでください。

3. **Save Changes**

### 1.7 Interactivity 有効化

1. **Features > Interactivity & Shortcuts** → ON
2. Request URL は入力不要（Socket Mode のため）
3. **Save Changes**

### 1.8 ワークスペースにインストール

1. **Settings > Install App** → **Install to Workspace** → **Allow**
2. Bot User OAuth Token（`xoxb-...`）をコピー → `SLACK_BOT_TOKEN`

### 1.9 チャンネル準備

1. Slack で `#ai-approvals` チャンネルを作成
2. `/invite @claude-bridge` で Bot を招待

### 1.10 自分の User ID 確認

1. Slack で自分のプロフィールを開く
2. **...** → **Copy member ID**（`U...`）→ `SLACK_APPROVER_USER_ID`

## 2. プロジェクトセットアップ

### 2.1 依存関係インストール

```bash
cd slack-bridge
uv venv && uv pip install -e ".[dev]"
```

### 2.2 グローバルインストール（推奨）

任意のディレクトリから `sb` コマンドを実行可能にする:

```bash
uv tool install /path/to/slack-bridge
```

`sb`（短縮コマンド）と `slack-bridge`（フルネーム）の両方が使用可能になる。

### 2.3 Claude CLI OAuth ログイン

```bash
.venv/lib/python3.*/site-packages/claude_agent_sdk/_bundled/claude login
```

ブラウザが開き、Max プランのアカウントで OAuth 認証する。API キー不要・従量課金なし。

### 2.4 環境変数設定

```bash
cp .env.example .env
```

`.env` を編集:

```
SLACK_APP_TOKEN=xapp-1-...
SLACK_BOT_TOKEN=xoxb-...
SLACK_CHANNEL=ai-approvals
SLACK_APPROVER_USER_ID=U...
```

**注意**: `ANTHROPIC_API_KEY` は設定しないこと。設定すると API キー認証が優先され、OAuth セッションが使用されない。

`.env` ファイルの探索順序:

1. カレントディレクトリ
2. パッケージインストールディレクトリの親
3. `~/.config/slack-bridge/.env`

## 3. 実行

### 3.1 デーモン起動

```bash
sb serve
```

`#ai-approvals` チャンネルに接続し、セッション受付を開始する。

### 3.2 セッション追加（推奨: `/claude` コマンド）

Slack チャンネルで `/claude` スラッシュコマンドを使用:

```
/claude ここにプロンプトを入力
```

`#ai-approvals` チャンネルにセッション開始メッセージ（スレッド親）が投稿され、以降の Permission/Question は個別のスレッド内に投稿される。

> **Note**: `sb run` コマンドは非推奨です。次版で削除予定のため、`/claude` コマンドに移行してください。

#### CLI からのセッション追加（非推奨）

```bash
sb run "ここにプロンプトを入力"
```

| オプション | 説明 |
|-----------|------|
| `--cwd /path/to/project` | 対象プロジェクトのディレクトリを指定 |
| `--tail N` | 過去バッファから N 行を取得（デフォルト: 100） |

### 3.3 セッション一覧

```bash
sb status
```

### 3.4 複数セッション同時実行

```
# Slack チャンネルで:
/claude プロンプト1
/claude プロンプト2
```

各セッションは Slack の独立したスレッドに紐付き、Permission/Question が互いに干渉しない。

> **Note**: CLI からの複数セッション実行（`sb run`）も引き続き動作しますが、`/claude` への移行を推奨します。

### 3.5 フルネームエイリアス

`sb` の代わりに `slack-bridge` も使用可能:

```bash
slack-bridge serve
slack-bridge run "プロンプト"
slack-bridge status
```

## 4. アーキテクチャ概要

```
┌─────────────────────────────────────────────────────┐
│  デーモンプロセス (sb serve)                          │
│                                                       │
│  ┌──────────────────┐  ┌──────────────────────────┐  │
│  │ SlackBot         │  │ SessionManager           │  │
│  │ (1 Socket Mode)  │  │                          │  │
│  │                  │  │  Session A ──► thread_A   │  │
│  │                  │  │  Session B ──► thread_B   │  │
│  │                  │  │  Session C ──► thread_C   │  │
│  └──────────────────┘  └──────────────────────────┘  │
│                                                       │
│  ┌──────────────────┐  ┌──────────────────────────┐  │
│  │ RequestBridge    │  │ IPC Server               │  │
│  │ (共有)           │  │ (Unix Domain Socket)     │  │
│  └──────────────────┘  └──────────────────────────┘  │
│                                                       │
│  ┌──────────────────┐                                │
│  │ AuditLog (共有)   │                                │
│  └──────────────────┘                                │
└─────────────────────────────────────────────────────┘

CLI (sb run) ──► IPC ──► デーモン: 新セッション起動
```

### Slack スレッド構造

```
#ai-approvals
├─ [Session A] プロンプト1         ← セッション開始メッセージ（スレッド親）
│  ├─ Permission Required: Bash   ← thread_ts でスレッド内に投稿
│  ├─ ✅ Bash → ALLOW
│  ├─ Question: ...
│  └─ ✅ Session completed
│
├─ [Session B] プロンプト2
│  ├─ Permission Required: Write
│  └─ ...
```

### ツール別動作

| ツール | 動作 |
|-------|------|
| Read, Glob, Grep, WebSearch, WebFetch, TodoWrite 等 | 自動許可（Slack に通知しない） |
| Bash, Write, Edit 等 | Slack スレッド内に Allow/Deny ボタンを投稿 |
| AskUserQuestion | Slack スレッド内に選択肢ボタン + 「Other...」ボタンを投稿。Other 回答は modal で入力。スレッド返信でも回答可能 |

### Slack スラッシュコマンド

| コマンド | 説明 |
|---------|------|
| `/claude <prompt>` | Slack から直接 Claude セッションを開始。設定チャンネル内でのみ使用可能 |
| `/claude-status` | 実行中のセッション一覧を表示 |
| `/claude-stop <session_id>` | セッションを停止 |

### Other 回答（modal 方式）

1. 質問メッセージの「Other...」ボタンをクリック
2. 入力 modal が表示される
3. 自由テキストを入力して Submit

### スレッド返信による回答

質問メッセージのスレッドに直接返信することでも回答できます。複雑な回答（長文テキスト、コードスニペット等）に便利です。

- 承認ユーザーからのスレッド返信のみ処理されます
- 複数の未回答質問がある場合、最も古い質問に回答が割り当てられます
- ボタン選択とスレッド返信は併用可能です

### タイムアウト

| 種別 | デフォルト | 動作 |
|------|-----------|------|
| 権限確認 | 300秒 | auto-deny |
| AskUserQuestion | 300秒 | auto-cancel |

環境変数 `PERMISSION_TIMEOUT_SEC`、`ASK_QUESTION_TIMEOUT_SEC` で変更可能。

## 6. トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| `ModuleNotFoundError: No module named 'src'` | `pyproject.toml` のビルド設定不備 | `uv pip install -e .` を再実行 |
| `ERROR: 環境変数 SLACK_APP_TOKEN が未設定です` | `.env` 未作成 or dotenv 未読み込み | `.env` ファイルをプロジェクトルートまたは `~/.config/slack-bridge/.env` に作成 |
| `Invalid API key` | `.env` に無効な `ANTHROPIC_API_KEY` が残っている | `.env` から `ANTHROPIC_API_KEY` 行を削除。OAuth ログイン済みなら不要 |
| `Invalid API key`（API_KEY 未設定時） | `claude login` 未実施 | Agent SDK 同梱 CLI で `claude login` を実行 |
| Slack にメッセージが届かない | Bot がチャンネルに未招待 | `/invite @claude-bridge` を実行 |
| `ERROR: デーモンに接続できません` | `sb serve` 未起動 | 別ターミナルで `sb serve` を起動 |
| `Another daemon is already running` | 別プロセスで `sb serve` が起動中 | 既存プロセスを終了するか、`SB_SOCK` 環境変数で別ソケットパスを指定 |

## 7. 監査ログ

全リクエスト/応答は `audit.db`（SQLite）に自動記録される。

```bash
# ログ確認
sqlite3 audit.db "SELECT timestamp, tool_name, decision FROM audit_log ORDER BY id DESC LIMIT 10;"
```

Slack 無料プランの履歴90日制限を補完する目的。ローテーションは手動管理。

## 8. Slack 権限棚卸し

### Bot Token Scopes

| スコープ | 要否 | 根拠 |
|---------|------|------|
| `chat:write` | **必須** | Permission/Question メッセージの投稿・スレッド内投稿に使用 |
| `channels:read` | **必須** | チャンネル情報取得に使用 |
| `commands` | **必須** | `/claude`, `/claude-status`, `/claude-stop` スラッシュコマンドに使用 |
| `channels:history` | **必須** | パブリックチャンネルのスレッド返信による質問回答に使用 |

### Event Subscriptions

| イベント | 要否 | 根拠 |
|---------|------|------|
| `message.channels` | **必須** | パブリックチャンネルでのスレッド返信検知に使用 |

### 権限変更後の再インストール手順

1. https://api.slack.com/apps → 対象アプリを選択
2. 上記の Scopes / Event Subscriptions を設定
3. **Settings > Install App** → **Reinstall to Workspace** で権限変更を反映
4. Bot がチャンネルに招待されていることを確認（`/invite @claude-bridge`）
