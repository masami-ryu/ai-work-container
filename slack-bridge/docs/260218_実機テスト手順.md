# slack-bridge 実機テスト手順書

作成日: 2026年02月18日

## 1. 前提条件

- Slack App の設定が完了していること（`docs/セットアップガイド.md` 参照）
- `.env` に必要な環境変数が設定されていること
- `claude login` による OAuth 認証が完了していること
- `uv pip install -e ".[dev]"` で依存関係がインストール済みであること
- Bot がテスト用チャンネルに招待されていること

## 2. セットアップ手順

### 2.1 環境確認

```bash
cd slack-bridge

# 依存関係の確認
uv pip install -e ".[dev]"

# 設定バリデーション（起動テスト）
sb serve
# → "Daemon ready" が表示されることを確認
# → Ctrl+C で停止
```

### 2.2 テスト用ターミナル準備

テストには最低2つのターミナルが必要:

- **ターミナル1**: `sb serve`（デーモン）
- **ターミナル2**: Slack チャンネル監視 & 操作記録

### シナリオ2: 権限承認フロー（P1-004 / TEST-002）

**目的**: Bash ツールの権限要求 → Slack 承認 → ツール実行の一連フローが動作すること。

**手順**:

1. ターミナル1で `sb serve` を起動（起動済みの場合はスキップ）
2. Slack チャンネルで `/claude List the files in the current directory using ls` を実行
3. 以下を確認:
   - [ ] 権限確認メッセージが表示される（Tool: Bash, Risk: warning）
   - [ ] コマンド内容（`ls` 等）が表示される
   - [ ] Allow ボタンが表示される
   - [ ] Deny ボタンが表示される
4. Allow ボタンを押下
5. 以下を確認:
   - [ ] メッセージが「✅ Bash → ALLOW」に更新される
   - [ ] Agent がコマンドを実行し、結果がスレッドに反映される

**Deny テスト**:

6. 同様のプロンプトで Deny ボタンのテストも実施
7. 以下を確認:
   - [ ] メッセージが「🚫 Bash → DENY」に更新される
   - [ ] Agent が deny を受けて別のアプローチを試みるか、エラーを報告する

### シナリオ4: タイムアウト（P1-006 / TEST-003）

**目的**: タイムアウト後に auto-deny が動作し、Agent が継続できること。

**手順**:

1. `.env` で `PERMISSION_TIMEOUT_SEC=60`（テスト用に短縮）を設定し `sb serve` を再起動
2. Slack チャンネルで `/claude Create a file called test.txt with the content "hello world"` を実行
3. 権限確認メッセージが表示されたら、**何も操作しない**で待機
4. 60秒後に以下を確認:
   - [ ] メッセージが「⏳ Write → TIMED OUT (auto-deny)」に更新される
   - [ ] Agent がタイムアウトを受けて次のアクション（別のアプローチ or エラー報告）に進む
5. テスト後 `PERMISSION_TIMEOUT_SEC` を元の値に戻す

**タイムアウト後のボタンクリックテスト**:

6. 新しいセッションで権限要求を待ち、タイムアウトさせる
7. タイムアウト後に Allow ボタンをクリック（メッセージ更新前の時点で可能な場合）
8. 以下を確認:
   - [ ] Ephemeral メッセージで「This permission request has already timed out」が表示される

## 5. UX 測定プロトコル（Phase 4 用）

Phase 4（Slack メッセージ最適化）の実機テスト（P4-005 / TEST-009）で使用する測定プロトコル。

### 5.1 対象端末

| 端末 | OS | 画面幅 | Slack バージョン |
|------|-----|-------|----------------|
| iPhone（SE以上） | iOS 最新 | 375pt以上 | 最新安定版 |
| Android端末 | Android 最新 | 375dp以上 | 最新安定版 |

### 5.2 ネットワーク条件

- Wi-Fi 環境（安定した接続）

### 5.3 試行回数

- 各端末で5回以上の権限確認操作を実施

### 5.4 測定指標

| 指標 | 測定方法 | 合格基準 |
|------|---------|---------|
| 通知確認→承認操作 | プッシュ通知のタップからAllow/Denyボタン押下までの時間 | 中央値5秒以内 |
| メッセージ表示範囲 | 権限確認メッセージが1スクロール以内に収まるか | 1スクロール以内 |

### 5.5 「1スクロール以内」の判定基準

- デフォルト文字サイズ
- 画面幅 375pt（iPhone SE相当）以上
- Slack アプリのスレッドビューで、メッセージ全体が初期表示領域に収まること

## 6. SDK メッセージ型調査

Phase 1 の実機テスト中に、`receive_response()` が返すメッセージの型を記録する。

### 6.1 調査項目

| 項目 | 確認結果 |
|------|---------|
| `AssistantMessage` の `content` に含まれるブロック型 | |
| `TextBlock` の挙動 | |
| `ToolUseBlock` の存在と構造 | |
| `ThinkingBlock` の存在と構造 | |
| `ToolResultBlock` の存在と構造 | |
| その他の未知のブロック型 | |

### 6.2 調査方法

`session.py` の `_consume_responses()` に一時的なログ出力を追加:

```python
async def _consume_responses(self, client, session):
    async for message in client.receive_response():
        # 調査用ログ
        logger.info("Message type: %s", type(message).__name__)
        if hasattr(message, 'content'):
            for block in message.content:
                logger.info("  Block type: %s, attrs: %s",
                           type(block).__name__, dir(block))
        # 既存処理
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if isinstance(block, TextBlock):
                    self._emit_output(session, block.text)
```
